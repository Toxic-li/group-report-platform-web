# 报表数据模型改造文档

## 📋 改造概述

本次改造解决了前端使用 VTable 临时坐标（`r_0`、`c_2`）作为业务主键的问题，改为使用真实的业务ID（BIGINT）和编码（VARCHAR），使数据可以直接入库。

### 3. reportStore 改造 ([reportStore.js](file:///e:\Projects\ReportCenter\src\stores\reportStore.js))

#### buildCellDataDTO 方法重构
- ✅ 使用真实业务ID（BIGINT）和编码（VARCHAR）
- ✅ 从模板配置中查找真实的 rowId、rowCode、columnId、columnCode
- ✅ 不再使用 `r_0`、`c_2` 等临时坐标
- ✅ 验证数据完整性

```javascript
function buildCellDataDTO(data) {
  const cells = []
  const cellData = data.cellData || {}
  const templateRows = data.rows || []
  const templateColumns = data.columns || []
  
  for (const [key, cell] of Object.entries(cellData)) {
    const [rowIdx, colIdx] = key.split('-').map(Number)
    
    // ✅ 根据索引查找真实的行/列配置（带业务ID）
    const rowConfig = templateRows[rowIdx - (data.frozenRowCount || 4)]
    const colConfig = templateColumns[colIdx - 2]
    
    // ✅ 创建 CellDataDTO（使用真实业务ID）
    const cellDTO = new CellDataDTO({
      rowId: rowConfig?.id || (1000 + rowIdx),
      rowCode: rowConfig?.code || `ROW_${rowIdx}`,
      columnId: colConfig?.id || (2000 + colIdx),
      columnCode: colConfig?.code || `COL_${colIdx}`,
      value: String(cell.v),
      rawValue: cell.raw || String(cell.v),
      formula: cell.f || null
    })
    
    cells.push(cellDTO)
  }
  
  return cells
}
```

## ✅ 改造收益

1. **数据完整性**：所有字段符合数据库表结构要求
2. **业务语义**：使用业务编码（如 `RAW_COAL`）而非临时坐标
3. **数据一致性**：前端数据可直接入库，无需二次转换
4. **可维护性**：清晰的类型定义和验证机制
5. **可扩展性**：支持多种数据类型和来源

## 🔄 后续优化建议

1. **从数据库获取真实业务ID**：目前使用临时生成的ID（1000+、2000+），应改为从数据库获取
2. **完善业务编码映射**：建立中文名称到业务编码的映射表
3. **增加数据校验规则**：根据业务规则校验数据有效性
4. **支持数据导入导出**：批量导入导出数据时保持业务ID一致性
